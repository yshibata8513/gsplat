# 3D Gaussian Splatting 学習時の性能劣化分析レポート

## 概要

3D Gaussian Splattingの学習において、時間の経過とともに処理が重くなる現象の原因を調査した結果をまとめる。

## 主要な発見：学習中のガウシアン数の動的増加

**結論：はい、学習が進むにつれてガウシアンの点数は大幅に増加します。**

### 1. 密度化戦略（Densification Strategy）による動的増加

#### 基本メカニズム
- **開始時点**: SfMから得られた初期点群（通常数万〜数十万点）
- **学習中**: 勾配情報に基づいて動的にガウシアンを追加・分割・削除
- **最終的**: 初期点数の数倍から十倍以上に増加することが一般的

#### DefaultStrategyの動作パターン
```python
# /workspace/gsplat/gsplat/strategy/default.py より

# 密度化実行間隔
refine_every: int = 100  # 100ステップごと
refine_start_iter: int = 500  # 500ステップから開始
refine_stop_iter: int = 15_000  # 15,000ステップまで継続

# 勾配閾値
grow_grad2d: float = 0.0002  # この値以上の勾配でガウシアンを増加

# サイズ閾値
grow_scale3d: float = 0.01   # 小さいガウシアンは複製
grow_scale2d: float = 0.05   # 大きいガウシアンは分割
```

### 2. 具体的な増加プロセス

#### Phase 1: 初期安定期（0-500ステップ）
- ガウシアン数: **一定**（初期値を維持）
- 既存ガウシアンのパラメータのみ最適化
- メモリ使用量: **安定**

#### Phase 2: 急激増加期（500-15,000ステップ）
- **100ステップごと**に密度化処理を実行
- 高勾配領域で新しいガウシアンを生成：
  - **複製（Duplication）**: 小さなガウシアンをコピー
  - **分割（Split）**: 大きなガウシアンを2つに分割
- **プルーニング**: 低不透明度のガウシアンを削除
- ガウシアン数: **指数的増加** → **線形増加**

#### Phase 3: 安定期（15,000ステップ以降）
- 密度化停止
- ガウシアン数: **一定**
- メモリ使用量: **安定**（ただし高い値で）

### 3. 性能劣化の具体的原因

#### 3.1 メモリ使用量の増加
```python
# ガウシアンあたりのメモリ消費量
per_gaussian_memory = {
    "means": 3 * 4,      # 12 bytes (3D位置)
    "scales": 3 * 4,     # 12 bytes (3軸スケール)
    "quats": 4 * 4,      # 16 bytes (クォータニオン)
    "opacities": 1 * 4,  # 4 bytes (不透明度)
    "sh0": 1 * 3 * 4,    # 12 bytes (SH 0次項)
    "shN": 15 * 3 * 4,   # 180 bytes (SH高次項、degree=3の場合)
}
# 総計: ~236 bytes/gaussian
```

#### 3.2 計算量の増加
- **ラスタライゼーション**: O(N) - ガウシアン数に比例
- **勾配計算**: O(N) - すべてのガウシアンで勾配計算
- **密度化判定**: O(N) - 各ガウシアンの状態をチェック

#### 3.3 GPU演算の複雑化
- **レンダリング**: より多くのガウシアンをソート・ブレンド
- **メモリ帯域**: データ転送量増加
- **並列処理**: スレッド間の競合増加

### 5. パフォーマンス最適化の観点

#### 5.1 設定による制御
```python
# 密度化を抑制する設定
strategy = DefaultStrategy(
    refine_stop_iter=10_000,    # より早期に停止
    grow_grad2d=0.0005,         # 閾値を上げて増加を抑制
    prune_opa=0.01,             # より積極的にプルーニング
```

## 推奨される対策

### 1. 短期的対策（即座に実行可能）
- `refine_stop_iter`を10,000程度に設定
- `grow_grad2d`閾値を0.0005に上昇
- `packed=True`でメモリ効率化

### 2. 中期的対策（設定調整）
- MCMCStrategy の検討（より制御された増加）
- バッチサイズの削減
- 画像解像度の調整

### 3. 長期的対策（アーキテクチャ変更）
- 階層的LOD（Level-of-Detail）システム
- 動的プルーニングアルゴリズム
- 分散学習の活用

## 結論

3D Gaussian Splattingにおける学習時の性能劣化は、**密度化戦略による意図的なガウシアン数の増加**が主原因である。これは品質向上のために必要なプロセスだが、適切な制御により計算コストとのバランスを取ることが可能である。

特に500-15,000ステップの期間で最大5-10倍のガウシアン増加が発生するため、この期間での監視と制御が重要となる。
